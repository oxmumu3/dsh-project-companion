| 微信提醒、日报与取消 | 旧版一次提醒、固定日报、取消及更新排版，均由用户手机回贴确认；测试计划清空 | 不扩大为新版主动跟进的手机证据 |
| 新引导首简报手机到达 | 用户回贴确认 `0.4.0-preview.1` 的首简报已到达 | 该条误读过时进度，不能证明摘要准确；整理资料后 `preview.2` 的正确摘要已在电脑原生会话验证，手机未再测 |
| 安装器防错 | 自动回归覆盖版本冲突、包篡改、运行中宿主、残留模块、禁用状态、升级和分步失败；本机真实 dry-run 与 CLI 升级通过 | 陌生用户下载后双击的完整开箱未测 |

## 已发现并修正的问题

- 旧摘要只给文件前 240 字，遗漏后半段阻塞。现将模型分析材料与手机短摘录分开，保留截断标记。
- 同一进度文件并存旧「待测」与新验收，导致首简报误读。固定来源整理为单一当前快照后，真实模型已正确总结；这一修正不能保证任意项目资料都准确。
- 冷启动时原绑定会话未加载，预览曾失败。现在仅在明确有效操作后恢复精确原会话；被动读取不恢复、不创建替代会话。
- 卸载并发曾可能提前移除只读守卫；已修复并增加真实插件生命周期回归。
- 网络失败后引导恢复、过期二维码显示、残留模块误判已安装等已修复并回归。

## 仍待验证

- 全新用户扫码、首条微信消息与首次简报的完整开箱；没有 Harness 的用户从官方应用安装开始的流程。
- 整理资料后的准确首简报在手机端的实际内容与显示。
- 连续多日、休眠、断网重连、来源会话不可用与失败恢复。
- 多用户部署、Windows 整合安装、与上游整包同时启用时的互操作。
- 更多真实项目的提炼质量，以及是否确实减少追问和操作。

微信桥接有每个交互窗口连续主动发送 10 条的限制，正常用户入站后恢复；通道回执不等于手机收到或已读。手机确认由用户本人完成，不使用微信客户端 UI 自动化。

## 本地重现

默认开发环境为 Node.js 22.13+，安装依赖后运行：

```sh
npm install --ignore-scripts
npm test
npm run demo
```

默认测试依赖固定为官方 SDK `0.2.0-rc.2`。兼容矩阵另使用官方 App 对应的 `0.2.1-rc.2` SDK，并设置 `DSH_TEST_SDK_VERSION=0.2.1-rc.2`；这不是仅切换环境变量就会替换依赖。测试不会启动完整 Desktop、真实模型或常驻服务；演示使用合成材料与模拟发送。安装和启用请走[官方插件页面或本地安装器](install.md)。
