# 持续事项：从发现到后续处理

0.21.0-preview.1 社区预览。安装入口见 README；既有账号、绑定和计划不会因升级自动扩大范围。

## 使用路径

1. 电脑端直接对话；微信连接后可以在手机接着交代。工作区范围、私人来源和定时回顾各沿用自己的明确授权，不相互扩大。
2. 选择工作区后点“保存并整理项目”，由一次明确动作连续处理本次快照；只想记住范围则点“仅保存范围”。中途可停止，已有结果保留。
3. 收到回顾后可说“准备个人回顾「事项原题」的下一步”。Dot 只整理这个已保存事项的已知信息、建议和待核对处，不额外读取、推算期限、派工或发送。
4. 明确交给原回顾范围内某个项目时，任务全文应写明个人回顾「事项原题」及要做的工作。模型可用准备结果中的内部事项索引关联普通项目交办；原 Family 真实消息、项目、原话和审批校验仍必须通过。受控独立只读入口暂不建立这种原生执行关联。
5. 项目执行回复进入原交办记录，并回写事项的执行状态。完成一轮只表示“待验收”；只有本人明确说已处理，才按既有反馈规则停止催促。关联滴答任务的状态与日期仍以滴答回读为准。

首页显示等待、正在整理、失败、来源未知和通道接受等实际记录。发送不确定时不会自动重发；没有任务也不会被说成没有变化。旧授权范围的记录不据此认定当前安排已运行。

## 新闻与关注

沿用已保存关注点、原 RSS 来源、3 篇精读加最多 7 篇概览和全部链接。相同网址忽略追踪参数；不同来源在同日有完全相同的长标题和 RSS 摘要时去重。摘要变更保留为新候选，不用语义猜测合并不同事件。近期历史只从实际通道接受或已有不确定发送的去重规则延续；预览不记作已发。历史旧记录缺少新身份时只沿用原文章 ID，不猜补历史来源。

## 复用与边界

参考 DeepSeek 的 MIT 研究原型 deepseek-ai/dsh-superagent-prototype（6337fc823ce20251c8de8085948165c81aaa701e）的任务与执行分离、持久结果思路；本轮没有拷贝它的代码或替换 Harness 运行时。继续复用 Dot 原有事项台账、原生 Coordinator、TaskResults、Owner/绑定/来源 lease、RSS 与模型实现。

用户分享的灵光研发复盘用于注意力管理、connector 与信任边界的产品输入，不作为其模型成绩或现有功能的独立验证。

电脑回归、实际宿主、日常安装、自然推送和手机收到分别记录；单轮通过不能证明多日、断网或休眠恢复稳定。
