# 第一次使用 DSH Dot

牛村木木山制作的社区项目，给已有官方 DeepSeek Harness 增加项目与微信流程。本页对应 `0.15.0-preview.14` macOS 社区预览，非 DeepSeek 或 OpenAI 官方产品。

## 选择已有入口，开始第一个项目

1. **新装公开版**：按[安装说明](install.md)准备官方 Harness，从[固定发布页](https://github.com/oxmumu3/dsh-project-companion/releases/tag/v0.15.0-preview.14)下载完整包。首次安装官方 Harness 后先打开一次以初始化桌面环境；保存并正常退出 Harness 后打开 `Install.command`，安装后重开。模型登录配置由本人完成；没有 Harness 时入口只指引安装官方应用。
2. 打开左侧「DSH Dot」。独立 Dot 已有兼容微信绑定直接沿用；第一次才点「连接微信」扫码，再从微信发一句「你好」建立会话。已有工作对话不会被首次引导抢走。
3. **已有共用家庭入口**：继续在原家庭微信对话使用，不重新扫码。Owner 委托须另行配置；当前 0.15 精确配套 Family `0.2.0-preview.33-diary.6-dot.3`。普通公开安装包只处理 Dot 与独立微信桥接，不自动安装或升级 Family。家人成员权限独立。
4. 按引导选一个持续关注项目，点「保存关注并预览简报」。最多关注五个；已有关注保留。0.15「项目」页另有全部已登记项目的搜索、分页和「单次查看」，不占关注名额。没有项目时在 Harness 左侧工作区添加一个本地项目文件夹，再点「已添加，刷新项目」；列目录不读正文，也不扫描电脑。
5. 点「生成首份简报并回到微信」。页面区分整理中、已生成与失败；停止或未生成内容时，可在原范围内明确重试。接收状态未知时不会自动重发，需要先核对原会话。只有手机实际看见后，才点「我已在微信收到这份简报」。重复进入不重发已接收的首简报；请求接收和内容生成不代表手机收到。

普通完整包包含 Dot 与独立微信桥接；共用家庭入口需要另行配置，不能把它当作安装包默认包含的能力。

## 把资料接到一份结果

先在「连接」页阅读用途说明，点击服务商官方登录并本人同意，再启用需要的来源。Google 三项数据权限已正式提交，目前 `UNDER_REVIEW`，未获批准、完成 CASA 或解除已知 100 账号上限；不保证任意新账号可用。flomo 需要 MAX，滴答只申请 `tasks:read`。本机 0.15 升级保留既有五源授权；授权、启用、实际读取和订阅分别记录，不需要为使用闭环反复重新登录。

在原微信对话指定来源、范围、条数与项目，先要一份简报，再交办一条小任务：

> 从 flomo 搜索 DeepSeek 最多2条，日历未来24小时最多2条，生成 我的项目 的项目简报。先不要建立计划。

> 把这个任务交给 我的项目：读取本项目的 README.md，用三句话说明项目用途，完成后把结果回给我。

把 `我的项目` 换成已关注项目名。第一条带来源整理资料，读取失败与零匹配分别说明；第二条保留冒号后完整原话，交给真实原生项目，沿用本机审批。受控 README 首行读取与普通任务是不同能力；共用入口的“只读／不要改文件”等表达仍走受控读取，不支持任意只读任务；普通原生任务不额外建立沙箱。多个目标不明确、目标忙碌或待审批时会说明，不把已接收当完成。

结果回原微信对话；后续查询进度不会重派。要跟进，再说「2分钟后检查 我的项目 的这份简报一次，有变化再告诉我，不要建立周期计划」。它沿用保存的范围，没有变化可静默结束，做完不留下周期计划。想持续跟进才明确频率，可随时取消；连接账号本身不会开启扫描。五源和每日/间隔示例见[快速开始](quickstart.md)与[个人资料闭环](context-loop.md)。

## 在电脑继续，核对真实状态

首页输入后点「开始对话」，草稿进入已有 Dot 原生会话，由本人发送；已有草稿保留。项目详情可查目标、阻塞、下一步和来源，在「记住的事」明确纠正或忘记记录；共用微信入口的记忆增改仍有限制，可在工作台操作。保存的项目笔记和助手回复不自动成为正式待办、测试或交付证明。

查看或安排跟进时先核对已有计划，再明确时间与范围。固定日报、按变化跟进和 AI 资讯是独立计划，首次引导不默认开启任何一种。暂停、撤权或换绑会阻断旧范围继续读取，取消不能撤回已交给通道的消息。

电脑与 Harness 需要在线，休眠或退出影响触发。微信连续主动消息受 10 条交互窗口限制，正常发一条消息后可恢复缓存；需要时说「继续收取刚才缓存的回复就好，不要重新执行任务，也不要新增提醒」。通道发送不等于收到或已读。
