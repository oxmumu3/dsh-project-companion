# Dot 首屏与对话接续原型

2026-10-30；本文件配套 `prototype.html`。这是交互方案，全部为虚构示例，仅在浏览器内存中改变状态。无远程依赖、网络读取、模型、微信发送、真实账号或计划；刷新重置。

## 这次取舍

- 保留批准的 V2 纸白、深墨、DeepSeek 蓝与今天／项目／记忆／连接四页。首页用两件有来源、有下一步的事项解释价值；完整历史在可发现的抽屉，不默认铺旧测试对话，也不删除历史。
- 输入、发送按钮和三个有明确用途的示例位于主列最前，事项列表随后；当前回复紧邻输入。首次浏览器 QA 发现原顺序把发送按钮挤出 1280×720 首屏，已按输入优先重排。右栏只放下一次示例安排和来源状况，既有计划未知不显示为关闭或零项。
- 顶部可切换日常／首次／连接问题。首次以“把 Dot 带到微信里”作为输入框上方的紧凑主卡，示意二维码直接展示，不再先点击按钮或进入弹窗。主卡说明手机交代、收结果与已开启提醒的收益及电脑在线条件。“先在电脑上试试”直接聚焦输入，不强迫扫码。图案中央标“演示”、旁边标“示意码 · 不用于连接”，不编码真实账号或令牌；小按钮演示扫码完成或过期，过期后在原位刷新。完成后主卡缩成成功状态；连接不等于已开订阅。连接问题只出现一条恢复提示，聊天和草稿继续保留。
- 首页点击右下 Dot 只定位聚焦原输入。其他页面点击即打开可输入的浮层，整个页面只有一个表单节点，在首页与浮层间移动，使用同一草稿与演示对话；关闭或 Escape 不清草稿。
- 风险卡“帮我拆成下一步”直接在当前区域展示这条通知的示例行动建议，保留未发草稿，不要求再搬运或发送口令。“演示发送”接受三个 starter 的精确文本，展示标明示例的固定回复。自由输入保留且明确说明未理解、未执行，避免假 AI。来源按钮打开虚构原文；标已处理、暂停和连接完成均仅改本页示例。

## 给主任务的浏览器走查

1. 1280×800 日常首屏：关注事项、来源与下一步能扫描，输入能发现，不由旧记录占屏。
2. 首页输入未发文字，点 Dot：不打开空浮层，草稿保留且获得焦点。
3. 带着草稿切项目，点 Dot：直接看到同一草稿并能编辑；Escape 后再次打开，草稿仍在。
4. 选择 starter 并演示发送：固定示例结果出现；可从历史找到该次对话。已有不同非空草稿时先保留到本页内存，显示“原草稿已保留／恢复原草稿”，恢复时当前编辑也保留，之后可用“切换暂存草稿”循环取回，不丢覆盖后继续修改的草稿。输入任意其他话并发送：不生成冒充分析的回复，草稿不丢。
5. 日常切首次、连接问题：首次直接看到示意码；顶部“微信未连接”和连接页微信按钮均回到该示意码，不开模态框。演示过期、原位刷新和扫码完成均保留草稿。连接页在首次时把微信排第一，右栏仅作可选资料说明。完成后首页显示紧凑成功状态且订阅仍未开启。不强迫填写表单；问题状态仍可聊天，重试只演示恢复、不另建安排。切换状态不清未发草稿。首次历史无旧记录；有本次演示互动时只显示本次记录。
6. 来源详情、历史抽屉支持键盘关闭与焦点返回；Tab 导航支持方向键。Enter 仅演示发送，Shift+Enter 换行，IME 组合不发送。
7. 390×844、720px 与桌面：输入、按钮、浮层不横向溢出；减动效模式无非必要动画。

## 当前边界

原型代码与静态检查已完成；主任务正在浏览器走查，已确认 starter 草稿保留／恢复及 Enter 示例发送通过，窄屏走查也已由主任务确认通过，其余最终 QA 以主任务记录为准，尚无用户认可。首次历史空态、已处理数量、连接问题旧结果及原安排未知文案已按 QA 修正；按用户最新反馈将首次微信示意码直接放到首屏；其他场景和草稿逻辑不变，该扫码状态流程等待主任务浏览器复验。生产端如何把首页事项投影与同一会话接起来、授权和状态如何可信回读，仍需实现与真实验收；不能把此 HTML 当已修好日常 Harness。
