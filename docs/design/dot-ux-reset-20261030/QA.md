# 可视方案走查

环境：Codex 内置浏览器的本地原型预览，1280×720 和 390×844；合成数据，不操作日常 Harness、微信、账号授权或真实计划。以下结果仅针对独立 HTML，原型可点不代表原生实现已交付。

## 必走路径

- [x] 日常首屏：输入和发送可见；当前事项、来源与下一次安排分列，旧聊天不占首屏。1280×720 发送按钮底边约 416px。
- [x] 点具体事项继续聊：点“帮我拆成下一步”出现对应参数风险示例建议，保留来源及未知边界，未发送草稿仍在。
- [x] 输入草稿后切项目页、打开 Dot：同一草稿，DOM 中只有一个输入表单；桌面与窄屏都实走。
- [x] 关闭浮层、回首页：草稿仍在；首页 Dot 入口聚焦输入、不打开空面板；Escape 后焦点回 launcher。
- [x] 历史入口可发现；日常态旧示例记录在抽屉中，不占首屏、不自动执行。
- [x] 首次使用：输入及发送可见，连接可稍后；未要求先配置全部来源。
- [x] 连接异常：顶部一个汇总恢复入口；旧结果标保存时间，不宣称没有待办；模拟重试保留草稿、不建真实计划。
- [x] 演示发送：固定示例通过 Enter 产生一份标注回复；任意输入只保留草稿，并明确未理解或执行。
- [x] Enter / Shift+Enter / Escape：已通过实际浏览器键盘操作；Shift+Enter 换行、不发送。
- [x] 390px 窄屏无横向溢出（documentWidth=390）；主发送按钮底边约 440px，浮层发送仍可见。
- [ ] 原生中文 IME：仅静态核对 `isComposing` 与 `keyCode===229` 防护，未模拟真实中文输入法，不能记为已验。

## 走查发现与修正

- 首版输入位于两张事项之后，1280×720 下发送按钮落到首屏外；已调到事项上方，保存失败图 `first-draft-input-below-fold.png`，不以大屏截图掩盖。
- 快捷提问原先直接覆盖草稿；已增加内存暂存与一键恢复，浏览器核对原文字逐字恢复。暂存仅存在本次页面，刷新会重置演示，不冒充真实持久化。
- 连接异常标题改为“上次留下的事，可以接着聊”，避免把旧结果说成今天的新发现。
- “另外两件”改为“事项待确认”，避免同一事项重复计数。

原生实现接线与全部真实来源问题见 implementation-gaps.md；本页不作为那些问题已解决的证明。

## 原生实现后另验

本 HTML 的简单输入不能代替原生 Conversation 的附件、引用、审批接管、草稿持久化、长历史加载与单实例切换。原生实现需按 native-implementation-audit.md 另行隔离 Host 测试；不静默更改 Harness 全局显示偏好，不以示例结果替代真实资料。

## 本人验收边界

代理走查只能确认这组样例的布局和操作；用户是否一眼理解、愿意日常用，仍由用户实际看这一版判断。手机收到、自然定时运行和 Google 审核不属于本原型验收。

## 冻结后的补充回归

- 独审发现恢复 A 草稿会覆盖编辑后的 B，已改为循环暂存。浏览器实际验证 A → 示例 → 编辑 B → 恢复 A → 切换 B，两份原文均保留。
- 首次使用历史为空，没有混入虚构旧验收记录；日常态历史仍保留。
- 连接异常中的“原安排仍保留”改为“原安排状态待确认，不会自动新建”，不从读取失败推断计划状态。
- 浏览器 console error 读取为空。真实 IME、附件、宿主审批仍属原生接线后的验收范围。
