# Dot 首屏与对话动线重做 · 2026-10-30

## 这轮解决什么

用户原话：“整个交互看着还是搓搓的，第一眼看不懂要咋用，咱真的有好好参考借鉴其他做的头部的 personal agent 吗”。用户截图证明：旧测试会话占满首屏；浮层无法直接继续输入；后台状态不明被拆成多个重复说明。此前原生组件、草稿和权限测试通过，不构成体验验收通过。

这轮交付可点击方案、任务走查与原生实现边界。原型中的资料、人物、安排和结果均是合成示例，不接账户、不发消息、不写真实计划。日常 0.18.0-preview.1 的运行、权限和计划保持原状；不把原型当成已安装版本。

## 首屏任务

用户应该能在同一屏完成三个判断：我能直接交代什么；Dot 已经发现了什么；接下来它会做什么。

1. 常驻输入是主入口。空态给出三条按目标命名的起步示例；点击只填草稿，不静默触发读取或发送。
2. 主动发现以具体事项呈现：发生了什么、依据是什么、为什么现在需要处理、下一步可做什么。来源不全就保留边界，不把模型推测展示成已发生的风险。
3. 对话接着事项继续，完整历史仍可发现。首页不自动铺满旧测试聊天，也不清除或重命名原历史以伪造整洁。
4. 已有安排用精简时间线展示。用户不必先阅读工作时段算法、授权 lease 或 Family 路由说明才能开始。
5. 资料不可用合并成一条具体恢复提示，同时区分仍可使用的能力。不能将未知改成“无待办”或用 CSS 隐藏错误。

## 同一个 Dot，两种入口

桌面可直接聊；微信是外出时的入口。任务、安排与跟进对应同一对象，但未同步的聊天历史不能假装已同步，家人私聊及权限继续独立。

当前首页已有可编辑对话时，悬浮入口直接定位并聚焦输入，不再打开“请回到工作台”的大面板。在其他页面点击悬浮入口，直接进入可输入的同一对话，关闭时保留草稿。正式实现坚持一个可编辑原生实例，沿用宿主审批和附件链，不单独抽取会绕过审批的底层输入组件。

## 三种必须走通的状态

| 状态 | 看到什么 | 下一步 | 不能伪造 |
|---|---|---|---|
| 首次使用 | 直接输入、三项示例、按需连接入口 | 说清目标，需要来源时就地连接 | 不假装已连接、已关注或已产生结果 |
| 日常使用 | 有来源的当前事项、输入、下一次安排 | 对某件事继续说一句 | 不默认展开旧测试记录，不重建已有安排 |
| 连接异常 | 一条说明影响的提示和恢复入口 | 未受影响的对话继续；只处理需要恢复的连接 | 不把状态未知当作没有任务，不自动扩大授权 |

## 视觉与操作

沿用批准的纸白、深墨、克制 DeepSeek 蓝；清晰的主列和紧凑次列，轻分隔代替层层卡片。状态及操作采用短中文，详细来源和覆盖范围按需展开。首屏输入可见，移动端不横向溢出；按钮有键盘焦点，Escape 关闭弹层并回到触发入口；中文输入法组合期间不得发送。

## 交付分层

- 外部一手依据：见 research.md。官网功能介绍、实际界面观察与设计推断分别记录。
- 可点击方案：prototype.html。支持首页/项目/连接、历史、当前事项继续聊、输入与浮层、三种示例状态。
- 原生实现范围：native-implementation-audit.md。公开 API 能力与待 Host 验证部分分开。
- 代理任务走查：QA.md。不能替代用户对设计的认可，也不证明真实来源读取、定时执行或手机收到。

日常自然主动运行、Google 审核继续按原任务推进；本轮界面方案不能作为这两项完成的证据。
