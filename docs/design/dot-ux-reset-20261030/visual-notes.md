# Dot 视觉细化记录

2026-10-30。仅更新 `prototype.html` 的 `<style>`，不改已认可的动线、文案、二维码状态、DOM、data hooks 或 JavaScript。`prototype-before-visual.html` 是精确内部对照，不是第二个对用户交付的版本。未修改生产源码、日常 Harness、其他设计文档或原型说明。

## 视觉约束

- 方向：纸白桌面工作伙伴，保留自己的 Dot 识别；设计重心是一张“电脑与微信配对卡”，周围安静。
- 画布：暖纸白 `#f6f5f0`，交互表面 `#fffefa`；轻分隔代替卡片套卡片。
- 字色：深墨 `#23313c`，正文辅助 `#606c76`；来源仍可辨，不靠极淡字制造精致。
- 动作色：蓝 `#345ec7`，浅蓝 `#edf2fc`；绿色仅用于已连接、已处理，琥珀仅用于待核对。
- 字体：中文系统无衬线承载正文、按钮与状态；宋体只用于适度的章节标题和配对卡标题，常规字重，不做大号粗宋体宣传页。
- 布局：保留四页与原顺序；输入与发送始终在主列前部。侧栏用单条分隔与时间线，状态和资料说明降低视觉重量。
- 图形：保留原 Dot 标识和二维码示意 SVG，没有新增品牌图形、插画、真实账号或可用二维码。
- 动效：只沿用轻量位移／按钮反馈，尊重减少动效；浮层全程不透明，不用整层透明度渐入。无渐变、光晕、模糊装饰或循环动画。

## 精确改动范围

1. 首次配对卡改成纸白说明区与浅蓝扫码区的结构化并列。二维码留有纯白静区；“演示／不用于连接”、过期遮罩、刷新和成功状态仍明显。
2. 输入区边框、焦点及发送按钮形成明确主动作；示例 starter 改为较轻的细边按钮，保留原行为。
3. tabs 采用小面积选中底色与细线；事项采用信息行与状态小标签，来源链接、下一步更易区分。
4. 侧栏统一时间数字、节点、标题和分隔；连接问题、已处理、成功提示共用相同色彩角色。
5. 轻入口与浮层统一边框、圆角和写作表面；未发草稿、焦点返回和单输入节点逻辑完全不变。
6. 窄屏主发送、刷新二维码及电脑替代入口不少于 44 px；保留 390 px 下紧凑扫码区与输入路径。小型演示控制不扩为大型产品动作。
