# 安装 DSH Dot 0.33.0

## 在创造模式中安装／更新

复制这段请求交给 Harness：

```text
请安装或更新并启用 DSH Dot。先检查现有插件，避免重复添加和降级。从 npm 官方源实时查询 @oxmumu3/dsh-project-companion 的 latest，按查到的精确版本安装或更新，不直接采用本机缓存的旧 latest。保留已有微信绑定、账号授权、资料范围、设置和其他插件，不自动读取或新建计划。核对实际版本、启用状态，再打开 DSH Dot。
```

新用户也可在「插件 → 添加插件」填写 `@oxmumu3/dsh-project-companion`（或精确版本 `@oxmumu3/dsh-project-companion@0.33.0`），安装后启用。它是一个标准插件包，已内置独立微信组件。已有未带 namespace 的历史安装应沿原包名更新；不要将两个名称当成同一个插件重复添加。

牛村木木山制作的 DeepSeek Harness 社区插件，非 DeepSeek 或 OpenAI 官方产品。本版内置微信组件，只需添加一个标准插件包，不包含 Harness 应用或 Family 家庭助手。

## 在 Harness 中添加一次

1. 首次使用官方 Harness，先打开一次完成初始化与模型配置。
2. 进入「插件 → 添加插件」，粘贴下面这一行，安装并点击「立即启用」。
3. 打开左侧「DSH Dot」，从首页连接微信，或先在电脑对话。后续授权工作区和个人来源分别按需进行。

```text
@oxmumu3/dsh-project-companion
```

网页版也可用命令行：`dsh plugin --profile web add @oxmumu3/dsh-project-companion`。

无法联网或想用离线包时，到 [Releases](https://github.com/oxmumu3/dsh-project-companion/releases) 下载对应版本的 `.tgz`，在官方管理器填写下载后的文件实际路径；无需解压、另装微信组件或运行 macOS 脚本。

[本版发布页](https://github.com/oxmumu3/dsh-project-companion/releases/tag/v0.33.0)记录本版变更。插件包从 npm 安装，npm 页面提供 integrity 与 provenance 可核；0.24 起 release 不再附带离线包。插件尚未上架官方插件市场，npm latest 同步为本版；不要用旧版 ZIP 或第二个微信安装包代替这条单插件路径。

## 已有用户

- 已配置的独立微信组件继续使用，包括已禁用、待加载或失败的状态；不会据服务暂未就绪就启动第二个组件。
- 已明确配置的家庭 Owner 共用入口继续沿用，不另开独立微信通道，不修改家人权限。
- 新用户的内置组件由 Dot 生命周期管理。停用 Dot 会一同释放其内置通道；外部独立微信插件不属于 Dot，不会被 Dot 停用或移除。
- 不改写 profile 依赖与插件配置，不调用第二次包安装，不迁移、重置或复制绑定/账号。来源启用、私人读取和持续安排仍分别沿用原有授权边界。
- 老独立组件版本不兼容或自身失败时，本版不会擅自升级它；需要在官方管理器处理该组件，不能把“保留现状”当成故障已修好。

## 宿主与运行条件

- 已支持的官方 SDK 为 `0.2.0-rc.2`、`0.2.1-rc.2`、`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.1-rc.5`、`0.2.2-rc.1`（rc.1 对应官方 Node 24.9 及以上，沿用宿主运行时，无需全局升级 Node 或版本豁免）。当前官方桌面验证在 macOS 完成，Windows 完整流程未验证；标准插件格式本身不等于所有平台已通过验收。
- 使用官方管理器完成安装、启用；需要重启时先保存工作并正常退出 Harness，不停止其他任务或手改 profile。
- 官方管理器安装仍可能需要联网获取正常依赖。本包不包含 Harness，不执行第二次插件安装，也不带自启动安装脚本。
- 独立受控主动推送需要宿主支持 Node 内置 SQLite；普通聊天可用不等于定时推送已经可用。
- 升级已有用户时保留旧组件和账号状态。旧组件不兼容或损坏时需单独处理，不将它误认成全新环境，也不自动降级或重置配对。

## 安装后先用起来

1. 打开左侧「DSH Dot」。首次首页直接显示微信二维码；已有兼容绑定沿用，第一次由本人扫码，再从微信发一句「你好」。也能先在电脑聊。
2. 想整理项目时，先选择一两个 Harness 已登记工作区，点「保存并整理项目」；明确发起后按每批最多8个连续处理，可停止并保留已有结果。点「仅保存范围」则不读正文、不开模型；后续在「连接」增减范围。
3. 项目是持续目标，目录是工作区，会话负责讨论和执行。保留识别建议或写明自己的目标，再从项目详情继续原生对话；不必把所有文件夹一次授权。
4. 需要个人资料时，在「连接」用服务商官方登录，由本人同意并启用所需来源。连接与启用不会自动开启推送。
5. 要回顾、日报或提醒时，用自然语言说清来源、项目、时间或频次，并核对保存的安排。电脑、Harness 和网络需在线。

完整操作见[首次使用](first-use.md)、[逻辑项目](logical-projects.md)、[个人回顾](personal-review.md)与[快速开始](quickstart.md)。

## Google、flomo、滴答

Google 普通三件套支持点击登录；授权保存在本机，普通刷新授权以 macOS Keychain 密钥 + AES-256-GCM 保存。高级手填配置、宿主记录和历史备份不在同一存储保证范围。来源返回内容可能进入配置的模型和微信回复，使用前阅读隐私说明。

Google 品牌已验证，Gmail、日历、Drive 数据权限已提交审核但未批准，CASA未完成、已知累计100个账号上限尚未解除，仍可能出现未验证提示或账号策略限制。不保证任意新账号都可用。若出现 “Google hasn’t verified this app”，核对 DSH Dot、开发者 experts@finvo.ai 和三项只读范围；愿意继续时，由本人选择 Advanced（高级）→ Go to DSH Dot (unsafe) → 继续／允许。这不代表 Google 已批准。保存成功后按用途启用来源。

授权回调依赖当前 Harness 进程存活。旧流程过期、App退出或重启后，从当前 Dot 重新发起，不刷新旧的127.0.0.1回调页；一次失败不会清除旧连接。flomo 需要 MAX，滴答申请 `tasks:read`。均可稍后再连。

## 共用已有家庭微信

本包不安装、升级 Family 或自动配置 Owner 委托。历史公开 `0.21.0-preview.1` 已配置共用入口的维护者组合为 Family `0.2.0-preview.33-diary.6-dot.3-travel.1-review.3`。此前日常升级保留了原绑定、五源账号范围、家人权限和安排；后续版本未覆盖安装维护者当前日常修复版，也不代表 Family 已完成 RC.4/RC.5 适配或新读者手机收件。未配置的读者先使用普通独立 Dot；家人成员不会获得 Owner 私人来源或项目权限。详情见[闭环说明](context-loop.md)。

## 本版验证与已知问题

0.33.0 源码全量回归 2,365 项 / 2,328 通过 / 0 失败 / 37 跳过（跳过项均需 Family 源码树，不在本包范围）。自检只读本机状态，不发外部请求；单项探测 2 秒上限，超时或抛错显示「未知」。私人外发确认只覆盖 `personal_review.run_now` 这条路径，宿主自带的 `send_wechat`、定时投递和带内容的 `remind` / `coordinate` 不经过这道门禁——插件单方面无法覆盖全部外发路径。

自动回顾仍为实验能力：自然语言 `focus` 尚未用真实模型验证实际效果，手机端呈现也未验证。历史 flomo 范围投影与模型失败未全部归因。新用户独立扫码到收件、多日与休眠恢复、真实 macOS 输入法仍分别验收。通道报告发送不等于手机收到。详见[验证记录](verification.md)。

## 来源与维护

微信能力复用固定维护基线，内嵌版补充二维码取消保护。来源、完整许可与可重建差异见[单插件说明](single-plugin.md)及[第三方声明](../THIRD_PARTY_NOTICES.md)。无需另装 YOLO、proactive 或微信插件整包。

包管理器可能按缓存或发布年龄策略把裸 `@latest` 解析为旧版。创造模式应先在线查询 npm 官方 latest，再安装查询所得的精确版本并回读实际版本；无需清理全局缓存或关闭全局安全策略。

## 微信首次配对

使用本人微信扫码并在手机确认后，内置组件直接锁定该账号；随后发送“你好”只是开始聊天，不参与抢先认领。入站白名单留空时仅允许扫码确认账号；填写后还会施加额外限制。无法确认身份或旧绑定冲突时，电脑微信设置页会给出恢复提示。重新扫码会保留原会话与归属于原账号的队列，本身不触发补发。独立安装的第三方微信组件保留其自身配对策略。

## 升级前自查

跑 `node scripts/validate-state.mjs`：只读本机状态，用当前包自带的 schema 逐个解析，列出不兼容的域与字段；返回 0 兼容、1 有不兼容、2 路径不存在。不启动 Host，不改文件。
