# 把个人资料接到项目下一步

当前源码及本机日常为 `0.15.0-preview.1`（`f57e5fb`），作者牛村木木山；公开下载仍为 [`0.14.1-preview.11`](https://github.com/oxmumu3/dsh-project-companion/releases/tag/v0.14.1-preview.11)。0.15 已完成电脑端核验，尚未公开，手机单份结果、提醒与一次跟进仍待本人确认。

## 先沿用自己的入口

独立 Dot 使用自己的 `dsh-wechat@0.11.1-dot.2`；公开完整包处理这条入口。共用家庭管家则沿用原家庭微信对话，只向已核验 Owner 开放个人资料与项目委托，家人成员权限独立。当前共用组合需精确的 Family `0.2.0-preview.33-diary.6-dot.2`，本机已安装；普通公开 Dot 完整包不会自动升级 Family 或建立共用关系。已有共用入口不用重扫码。

两条入口不保证任意语句、任意工具完全等价。下面采用共用 Owner 入口支持的明确原话；普通原生会话仍可使用独立 Dot 已有的模型工具流程。

## 找到项目，限定资料，交办一件事

先说：

> 列出我的 Harness 项目。

可按回复翻页，或说“搜索我的 Harness 项目「写作」”。列的是全部已登记项目的分页目录，不是最多五个关注项目，也不是前十项候选。列目录不读取项目正文。电脑「项目」页可再点「单次查看」，读取选中项目三份固定说明，不占关注名额、不读聊天历史、不建计划。资料简报先使用已关注项目。

把 `我的项目` 换成具体项目名：

> 从 Gmail 搜索「subject:DeepSeek」最多1条，日历未来24小时最多2条，Drive 搜索「DeepSeek」最多1条，flomo 搜索 DeepSeek 最多2条，滴答清单列出清单最多2个，生成 我的项目 的项目简报。先不要设置提醒，不要建立计划。

Dot 保存各来源范围，结合项目资料整理有引用的进展、阻塞与下一步。零匹配、缺项、截断和读取失败分别保留；本例滴答仅列清单，不冒充任务正文。共用入口还支持“滴答「工作」清单的未完成任务最多2条”；先精确匹配清单名称，再有限读取，不做全账号任务搜索。Google 数据权限仍 `UNDER_REVIEW`，未获批准、完成 CASA 或解除已知 100 账号上限；flomo 需要 MAX。

要执行时，另发一条：

> 把这个任务交给 我的项目：读取本项目的 README.md，用三句话说明项目用途，完成后把结果回给我。

共用入口要求明确项目与冒号后完整任务原话，目标是原生 Harness 项目/会话，沿用本机审批。目标忙碌、多个会话无法唯一确定或需要审批时如实说明，不改投别处，不把已接收称为完成。先有简短接收确认，随后一份最终结果回原微信对话；主动查询进度不重新派工。结果未知时不盲重派，只有确认未派发且本人再次明确要求时才作有界重试。

共用入口的“只读／不要改文件”等表达仍走独立受控读取，不支持任意只读任务；普通原生任务沿用项目工具与审批，不额外建立技术沙箱。独立 Dot 原有“把刚才第二项交给这个项目”的简报编号交办，不等于共用入口已支持任意编号任务；共用入口的一般任务用上面的完整项目交办句。

## 有范围地跟进，没变化就安静

先有一份保存范围的简报，再明确时间：

> 2分钟后检查 我的项目 的这份简报一次，有变化再告诉我，不要建立周期计划。

或者：“每30分钟检查 我的项目 的这份简报，有变化再告诉我”“北京时间每天21:30给我 我的项目 的资料简报”。范围与时间从本人真实微信原话核验，沿用该简报选定来源；不因连过账号而扩大读取。未说频率不建周期计划，表达不明先补充。

共用入口支持 1–5 分钟后的一次检查、30–1440 分钟间隔和一个明确每日时间。每日按所说时区，未说则用电脑时区，明确每日时间可夜间触发；间隔跟进遵守电脑时区 23:00–08:00 免打扰。“未来24小时”保存为滚动窗口，每次检查以当时为起点；固定日期仍固定。

可说“关闭 我的项目 的主动跟进”或“取消 我的项目 的单次检查”。普通聊天不关闭已有订阅；暂停助理、撤权、换绑、取消关注、取消或替换范围会阻断旧订阅。单次检查完成不留周期计划，没有新变化时保持安静。临时失败保留未知，同一缺项不会反复推送，也不当作已解决。

## 复用与数据边界

| 环节 | 已有能力与当前衔接 |
| --- | --- |
| 资料 | Google、滴答、flomo 读取器与权限检查；每来源独立查询，不混用参数 |
| 简报 | 宿主模型、项目资料和记忆；保留目标、引用、范围与版本 |
| 交办 | 既有 Coordinator、TaskResults 和微信桥接；原话授权、目标审批、持久去重与原通道结果 |
| 跟进 | 已保留许可的 proactive 调度器；只运行保存范围，无变化静默 |
| 工作台 | 今日 / 项目 / 记忆 / 连接；自然语言草稿、全部项目目录、范围与计划管理 |

没有另建微信通道、连接器、模型服务或定时系统。nanobot、Hermes、OpenClaw 的连续任务思路只作设计参考，未复制实现；vendored YOLO/proactive 与微信桥接版权见[第三方说明](../THIRD_PARTY_NOTICES.md)。

- 每个原会话、已关注项目保留一份活动范围，最多五项查询，每来源一次、每项最多三条，最多九个有依据的简报条目；主日历不等于全部日历。不承诺扫描完整账号或支持任意资源 ID。
- 连接、启用、实际读取与订阅分开。授权来源不会自动创建扫描、计划或长期记忆。改范围、换绑或重新连接后，旧计划不能继承新权限。
- 摘要、范围、引用与少量摘录保存在本机 `project_companion_context_loop` 域；完整邮件/文档响应与凭据不复制进该域。资料仍会进入 Harness 会话和所配置模型，通过微信回复还经过微信通道，不承诺永不离开电脑。
- 简报编号不是正式待办系统，滴答状态以源系统为准。工作台支持记忆纠正/忘记，共用微信入口的记忆增改仍有限制。
- 执行结果最多取 600 字供后续提炼，标明助手来源与截断。原结果由既有账本回传一次，跟进不再创建第二份结果；通道接收不等于手机收到。
- 电脑、Harness 与通道需可用。无微信绑定的原生会话可整理资料，交办结果关联与主动送达不作同等保证。取消不能撤回已开始回合或已交给通道的消息。
- AI 资讯仍用原独立来源、入口与频次，不默认从私人资料推断兴趣，不重复塞进项目简报。

## 当前验证与剩余验收

冻结 Dot `f57e5fb` 与配套 Family 的候选包，在 Harness `0.2.0-rc.2`、`0.2.1-rc.2`、`0.2.1-rc.3` 三套 SDK 各 1280/1280，零失败、零跳过；独立审读、隔离官方 Host 与四页原生界面另有核验。日常 App 的两组件已启用且 active，原微信与五源授权、家庭权限/计划/消息保留；重连仅清掉三个可选收发时间显示字段，不称重开后所有状态字节完全不变。

维护者本机证据在 `output/dsh-dot-overnight-2026-10-28/` 的 `delivery-manifest.json`、`daily-native-ui-proof.json`、`matrix/matrix-result.json`、`integrated-review.json` 和 `微信一次性验收.md`，不随公开包分发。本轮电脑核验未读取真人私人来源、未发微信或创建真实计划。

手机简报、普通原生交办的一份结果、到时提醒与一次范围检查仍待本人一次确认；滴答任务正文实读、任意新账号接入、新用户完整开箱、长期稳定与休眠重连分别待验。旧版有限 flomo＋日历简报、受控 README 首行和提醒的手机收件见[历史验证记录](verification.md)，不代替本候选验收。安装区分见[安装说明](install.md)，下一步见[路线图](roadmap.md)。
