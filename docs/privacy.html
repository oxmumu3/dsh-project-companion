DSH Dot 如何使用资料

DSH Dot 是运行于用户自己电脑上的 DeepSeek Harness 社区插件，帮助用户在 Harness 或已绑定的微信对话中查看项目、查询本人已授权的资料，并按明确要求安排项目提醒和汇报。Google 连接用于用户可见的邮件问答与摘要、日程查询、文件检索与内容问答。维护者不经营用于集中代存用户 Google 令牌或私人资料的 Dot 后端服务器。

申请哪些 Google 权限

权限用于什么
Gmail 只读
gmail.readonly		按查询读取有限的匹配邮件元数据、摘要，以及明确选择邮件的限长纯文本内容。当前不下载附件，不发信、不修改或删除邮件。
日历事件只读
calendar.events.readonly		查询主日历中指定时间段的事件。默认未来 24 小时，可限定到最多七天、十项。不新建、修改或删除日程。
Drive 只读
drive.readonly		查询文件元数据，读取明确指定文件支持的内容，例如文档或幻灯片纯文本，以及指定表格范围。不修改、删除或分享 Google 文件。

这些 OAuth 权限本身的覆盖范围比一次查询更大。Dot 在工具代码中继续限制具体操作、时间段、返回数量与内容长度。只有实际获授权并被启用的来源可用。连接 Google 本身不读取邮件或文件正文，也不自动建立私人资料的持续扫描、监控或推送计划。

资料如何被处理和传递

登录在 Google 官方页面完成，令牌交换和 Google API 请求由本机直接发往 Google。读取结果用于回答你提出的问题，可能进入 Harness 当前会话、宿主记录及你配置的模型上下文。选择云端模型时，相关资料会发送给该模型服务商；通过微信接收回答时，回答还会经过所使用的微信桥接服务和微信通道。因此，本机保存授权不代表资料始终只在电脑上。

这些传递只应用于你明确请求、界面可见的辅助功能。启用 Google 来源前，你选用的模型服务必须允许将这些资料仅用于你请求的功能，并保证不把它们用于通用 AI 模型训练或其他不符合 Google Limited Use 要求的用途；无法确认时，请勿启用 Google 来源。维护者不能替你选择的独立服务商保证其保留期限、人员访问和训练政策，也不能通过用户同意免除 Google 对应用本身的要求。

Dot 没有将 Google 资料出售、用于广告、信用评估，或为维护者训练通用 AI 模型的功能。支持邮件、公开 Issue 和贡献流程不要求用户提交私人内容或授权令牌；维护者不会因为你安装插件而获得你的账号访问权限。

宿主日志与模型改进

DeepSeek Harness 另有「使用官方模型 API 时上传会话日志」设置，官方设置说明的用途包含改进模型和产品。开启时，宿主可能在官方模型请求中附带会话事件日志；Dot 的令牌加密不会阻止这条独立路径。0.14.1-preview.11 不会自动关闭该设置。使用 Google 来源前，应在 Harness 设置中关闭这项上传，并核实实际模型渠道的训练及保留条款；关闭该开关本身不代表普通推理请求已经取得不训练保证。DeepSeek 账号及 API 通道的相关书面确认尚未取得，不能仅凭付费或会员身份推断。

本地保存与保留

在 0.12.0-preview.4、0.13.0-preview.2 和 0.14.1-preview.11 中，通过普通「连接 Google 三件套」或「只连接 Google 日历」保存的授权 JSON 使用 AES-256-GCM 加密后进入 Harness 本机 profile；每次保存的独立随机密钥保存在 macOS Keychain，访问令牌只在授权控制器内存中缓存。无法读取钥匙串或验证密文时不会降级为明文保存。这项保证只覆盖上述两种普通 Google 登录，不覆盖高级手填的刷新令牌、flomo/滴答凭据、资料简报记录、Harness 会话或历史备份。

此前公开预览版 0.12.0-preview.3 将普通授权保存在本机 profile，没有应用层静态加密保证。升级安装不会自动迁移所有旧凭据：已有这两种普通 Google 明文记录仅在你明确查询、需要获取 Google 令牌前，经权限检查和原生配置事务后迁移；单纯查看状态或刷新页面不会迁移。重新登录可用新授权替换旧记录。旧备份不会被自动改写。

本机授权引用保留至你清除；为避免无法判断的宿主写入产生不可解密记录，部分 Keychain 密钥可能在写入结果不确定时保留。清空 profile 不等于清理所有钥匙串遗留项、会话或备份。Google 端访问许可也可能因到期或撤销而失效。

在 0.14.1-preview.11，单次读取来源不等于自动把完整 Google API 响应写入项目记忆。你明确要求生成资料简报并成功完成时，Dot 会在本机 Harness 的资料简报存储中保存该次有限查询范围、生成的摘要和事项，以及带来源标识、时间、标题等信息和最多 300 字符原文摘录的引用；短内容的摘录可能包含全部内容。简报可供该项目的后续交办或你明确开启的跟进使用。模型整理失败时可能返回限定范围内的原文摘录；这种降级回复本身不创建上述简报记录，但仍可能保存在会话或宿主记录中。用户或助手消息的有限摘录也可能进入已关注项目的近期记录。当前没有统一的自动清理期限。你自行复制、备份或发送到其他服务的内容，需要在相应位置分别管理。

停止、清除与撤权

  1. 在「DSH Dot → 连接与设置」对来源选择「停止此来源」，停止它在当前对话中的后续读取。
  2. 在连接页的高级凭据设置中选择「清除 Google 三件套授权」或「清除 Google 日历授权」，再点击「保存连接凭据」，清除相应本机授权记录。若两种授权都保存过，可分别清除。
  3. 在 Google 账号的第三方连接管理页撤销 DSH Dot 的访问。这会撤销 Google 端许可；仅停止 Dot 来源或删除本机记录不会替你完成 Google 端撤权。
  4. 停止来源或撤销 Google 授权不会自动删除已保存的资料简报循环、摘要、来源摘录、会话或备份，也不能撤回已交给模型服务或微信的内容。可要求 Dot 停止并忘记对应项目的资料简报循环；已交办记录、宿主会话、项目记录、备份以及第三方服务中的副本须分别管理。删除能力以实际入口与权限为准；需要帮助定位本机记录时可联系维护者，请勿向公开 Issue 发送令牌或私人正文。

0.20 个人回顾、逻辑项目与保存记录

本版继续使用上述Google只读权限和普通授权加密存储，不新增Google权限。个人回顾仅在本人明确选择来源、项目、范围和时间后订阅；工作时段关注也需明确开启。保存连接或新增工作区不会自动开启扫描，也不会静默扩大旧计划。按约定时间读取的有限资料会交给已配置模型整理，投递到原微信时经过桥接与微信通道。

个人回顾在本机保存有限事项、来源引用、摘要、本人反馈、范围、运行和投递元数据，当前最多300条事项、60条运行与800个调度记录；不保存整批来源原文，但内容可能已进入会话或宿主记录。项目简报保存有限查询范围、摘要及来源摘录；0.20中模型整理失败时也可能保留可辨认的资料摘录和范围，后续只能沿用已确认范围。逻辑项目保存用户目标、约束、识别建议和有限来源关联；将内容带入专属原生会话后，会话仍有自己的记录。

本版不会替用户自动关闭宿主会话日志上传，也不能据开关关闭保证普通推理请求不训练或不保留。停止来源、取消安排或撤回工作区范围会阻止相应的新读取，但不会自动删除旧项目目标、摘要、原生会话、备份或第三方已收到的内容。可用的忘记／删除入口有各自范围，没有一键统一删除所有副本的保证。

Purpose and access

DSH Dot is a community plugin running in DeepSeek Harness on your computer. It supports project assistance and questions about sources you authorize, through Harness or a connected WeChat conversation. Google access supports visible email questions and summaries, calendar queries, and file search and questions. The maintainer does not operate a Dot backend that centrally stores users’ Google tokens or private content.

  • gmail.readonly: limited matching message metadata and snippets, plus bounded plain text from a message you select. The current implementation does not download attachments or send, modify, or delete mail.
  • calendar.events.readonly: primary-calendar events for a bounded period. The default is the next 24 hours, with up to seven days and ten events supported. It does not create, modify, or delete events.
  • drive.readonly: file search metadata and supported content from a specified file, such as document or slide text and a specified spreadsheet range. It does not modify, delete, or share files.

OAuth scopes cover more than a single query. Dot also bounds operations and result size. Only actually granted and enabled sources can be used. Connecting Google does not itself read mail or file bodies or start continuous scanning or private-source pushes.

Processing and recipients

Login takes place on Google’s official pages. Token exchange and Google API requests go directly from your computer to Google. Retrieved results may enter Harness conversations, host records, and the context sent to your configured model. Cloud models receive relevant content. Answers delivered through WeChat also pass through the configured bridge service and WeChat channel. Local authorization storage does not mean all content always stays on your computer.

Before enabling Google sources, use a model service that restricts this data to your requested features and does not use it to train general-purpose AI models or for other uses outside Google’s Limited Use requirements. If you cannot confirm this, do not enable Google sources. The maintainer cannot guarantee independent providers’ retention, human-access, or training policies. User consent does not waive the application’s own Google-policy obligations. Dot has no feature to sell Google data or use it for advertising, credit decisions, or general-purpose training for the maintainer.

Host session logs and model improvement

Harness also provides an “Upload session logs when using the official model API” setting. Its official description includes improving models and products. If enabled, the host may attach conversation-event logs to official-model requests; Dot’s token encryption does not prevent that separate path. Version 0.14.1-preview.11 does not automatically turn this setting off. Before using Google sources, disable this upload in Harness settings and verify the actual model channel’s training and retention terms. Turning this switch off does not by itself establish a no-training commitment for ordinary inference requests. Written clarification for DeepSeek account and API channels has not yet been obtained; paid or membership status alone is not proof.

Storage and retention

In 0.12.0-preview.4, 0.13.0-preview.2, and 0.14.1-preview.11, OAuth records saved through the ordinary Google suite and Google Calendar login flows are encrypted using AES-256-GCM in the local Harness profile. Separate random encryption keys are stored in macOS Keychain; access tokens are cached only in the authorization controller’s memory. The ordinary flow does not fall back to cleartext storage when Keychain access or ciphertext validation fails. This protection covers only those two ordinary Google login flows, not manually entered advanced refresh tokens, flomo or Dida credentials, context-brief records, Harness conversations, or historical backups.

Prior public preview 0.12.0-preview.3 saved ordinary authorization in the local profile without an application-level encryption-at-rest guarantee. Installing an upgrade does not automatically migrate all old credentials. The two ordinary Google records are migrated through guarded native configuration transactions only when an explicit query needs to obtain a Google token; merely viewing or refreshing status does not migrate them. Reconnecting can replace an old record with new authorization. Historical backups are not rewritten.

Local authorization references remain until cleared. To avoid making a possibly committed record undecryptable, a Keychain key may remain when a host-write outcome is uncertain. Clearing the profile is not deletion of all residual Keychain items, conversations or backups. Google-side permission may also expire or be revoked.

In 0.14.1-preview.11, a single source read does not by itself automatically copy the complete Google API response into project memory. When you explicitly request a context brief and it succeeds, Dot stores the bounded query scope, generated summary and items, and source references including identifiers, timestamps, titles and verbatim excerpts of up to 300 characters in local Harness context-brief storage. An excerpt may contain the entire content of a short item. The brief may be used for a later handoff for that project or follow-up you explicitly enable. If model processing fails, a bounded source-excerpt response may be returned; that fallback itself does not create the above brief record, but it may still remain in conversations or host records. Limited user or assistant message excerpts may also enter recent records for a watched project. There is no unified automatic retention period. Manage your own copies, backups, and content sent to other services at those locations separately.

Stopping access and deleting records

  1. In DSH Dot → Connections and settings, select “Stop this source” to stop further reads through that source in the current conversation.
  2. In advanced credential settings, select “Clear Google suite authorization” or “Clear Google Calendar authorization”, then save the connection credentials. Clear both separately if both were saved.
  3. Revoke DSH Dot in your Google Account’s third-party connections page. Stopping a source or removing its local record does not itself revoke Google-side permission.
  4. Stopping a source or revoking Google authorization does not automatically delete saved context-brief loops, summaries, source excerpts, conversations, or backups, and cannot recall data already sent to a model provider or WeChat. You may ask Dot to stop and forget the relevant project’s context-brief loop; separately manage any handoff records, host conversations, project records, backups, and copies held by third-party services. Available deletion actions depend on the actual entry point and permissions. Contact the maintainer for help locating local records; do not post tokens or private content in public issues.

Google data-use rules

The maintainer requires this project’s use and transfer of information received from Google APIs to adhere to the Google API Services User Data Policy, including the Limited Use requirements. Data must be used only for that user’s requested, visible features. It must not be sold, used for advertising or credit decisions, or used to train AI beyond an appropriate personalized use for that specific user. The configured model and other recipients must satisfy the same purpose limitations.

This notice describes current behavior and project rules; it is not a claim of completed Google verification or a security assessment. See also the Google Workspace user data and developer policy.

0.20 personal reviews, logical projects and saved records

Version 0.20 uses the same read-only Google scopes and ordinary encrypted authorization storage. Private-source reviews require an explicit selection of sources, projects, scope and schedule; work-hours attention requires separate enablement. Connecting an account or adding a workspace does not start scans or silently extend existing subscriptions. Bounded scheduled results are processed by the configured model and may pass through the WeChat bridge and channel.

Local review storage retains bounded items, source references, summaries, feedback, scope, run and delivery metadata: currently up to 300 items, 60 runs and 800 schedule records. It does not retain whole source batches, but content may remain in host conversations or logs. Context briefs retain bounded scope, summary and excerpts; in 0.20 a failed model analysis may also leave a source-excerpt result and saved scope for explicitly authorized follow-up. Logical projects retain user goals, constraints, suggestions and bounded source associations. Native project conversations have their own records.

This version does not automatically disable host session-log uploads. Disabling that setting alone is not a no-training or retention guarantee for normal inference. Stopping sources, subscriptions or workspace access prevents applicable new reads; it does not automatically erase old goals, summaries, conversations, backups or recipients' copies. Forget and delete controls have their own scope; there is no guarantee of one action deleting every copy.
