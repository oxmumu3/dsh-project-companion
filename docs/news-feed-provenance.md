# AI 日报信息源与实现边界

## 来源

本版沿用用户既有 AI Daily Digest 的 **92 个独立技术博客 RSS 地址**。它们包括 AI、软件工程、安全、工具与个人观点，并非 92 位 AI 专家，也不代表每天都有 10 篇符合主题的新文章。

地址核对来源：

- [vigorX777/ai-daily-digest 固定版本的公开 RSS 地址](https://github.com/vigorX777/ai-daily-digest/blob/1f484a3f2f101cb0f1a94a35b1a1befe0f672b82/scripts/digest.ts)
- 上游说明链接的 [Hacker News Popularity Contest](https://popularity.refactoringenglish.com/)，由 Refactoring English 维护。

2026-10-19 核对时，本机清单与上述固定版本的 92 条 `name / xmlUrl / htmlUrl` 地址事实逐项一致，URL 均唯一。上游 README 写作“90 个”与实际 92 条有出入，本项目按实际打包清单计数。

上游 README 称 Karpathy 推荐了这些博客，但只链接他的个人主页；本轮没有核实到原始推荐帖，因此公开产品说明不将该说法写成已核实背书。

## 许可证与署名

核对时，`vigorX777/ai-daily-digest` 固定版本根目录没有 LICENSE，GitHub repository API 的 `license` 为 `null`。另一个实现 [HarrisHan/ai-daily-digest](https://github.com/HarrisHan/ai-daily-digest/tree/331ccaf62b8f5e1780259aaf396b23169e8fe6c5) 的 README 写有 MIT，但该版本同样没有单独 LICENSE 文件，因此本项目没有把它的代码当作已确认许可的依赖。

本项目仅记录公开博客地址事实并保留来源署名；**未复制上述项目的脚本、解析器、模型提示词、评分、摘要、调度或配置逻辑**。`src/news-feeds.js` 独立实现且不新增第三方解析依赖，由本项目的 MIT 许可证覆盖。这个 MIT 声明不延伸到上游项目、博客文章或第三方站点内容。

各博客的文章与 RSS 内容仍归相应权利人；日报只提供自己的摘要和原文链接。原文抓取只供本次摘要使用，按有界文本处理，不将全文打包进插件或作为公开文章档案。

## 抓取与可核查范围

- 只抓固定清单里的 RSS 地址；调用方可选择其子集，不能注入任意 URL。
- 最多 4 个并发，每次源读取总计 8 秒、512 KiB；整轮源扫描最多 45 秒，保留已成功的源并报告未完成范围。统计 `failedFeeds` 表示全部未获取的源，其中 `skippedFeeds` 单独计数因整轮截止而尚未尝试的源，不能将跳过直接解释为来源本身失效。
- 固定来源清单的扫描起点按 UTC 日期逐日轮换；同一 UTC 日顺序稳定，每轮每个选定源最多读取一次。轮换用于减少固定尾部持续未扫描的偏差，不增加来源、不更改域名/URL 校验，也不证明每天全量覆盖；实际范围仍看当轮统计。
- 默认 HTTP(S) 运输把已验证公网 DNS 地址固定到实际连接；拒绝私网、回环、保留地址、凭据 URL 和非标准端口。每一跳重定向重新检查清单域名和 DNS，最多 3 跳。
- 支持 RSS 2.0 和常见 Atom 字段；拒绝 DTD、实体声明和不闭合的 XML。单向扫描最多处理 12,000 个标记，单个标签最多 8 KiB，XML 嵌套最多 128 层；不使用跨全文重复回溯来寻找闭合标签。不执行 XML、HTML、脚本或 RSS 中的指令。超出边界的源失败计数，畸形正文回退 RSS。
- 只保留明确发表在所选时间窗口内的文章，剔除未知日期、未来日期和重复链接；最多交给模型 100 个候选，每篇 RSS 摘录最多 800 字符。
- 详读只访问同一来源的已知博客域名，网络上限同上，最多提供 24 KiB 的抽取正文。`coverage: article` 表示读到了有界正文，并不保证全文完整；`truncated` 明示文本截断。失败时返回 `coverage: feed-only`，明确只读到 RSS 摘录。
- 扫描不足、源不可用、正文不可读必须进入日报的证据边界。没有足够合适文章时，实际少于 10 篇，不捏造内容、不以旧文冒充今日新闻。

以上限制是当前实现范围，不代表已证明所有 92 个源长期可达、正文抽取完整或文章事实正确。
