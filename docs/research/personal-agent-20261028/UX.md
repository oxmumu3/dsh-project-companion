# 从“看懂界面”到“走到结果”的三项交互增量

本轮不是给“全网最佳”排榜。选取已读的一手设计体系，与真实产品流程、0.15 源码和已有四页截图交叉核对。没有竞品完成率、首次成功用时或审美偏好样本。

## 三个一手依据

| 依据 | 已核的设计方法 | 对 Dot 的约束 |
| --- | --- | --- |
| [Google PAIR：Explainability + Trust](https://pair.withgoogle.com/chapter/explainability-trust/) | 解释应帮助用户校准能力与边界，并在其采取动作时说明数据怎么用；缺资料要明说。 | 披露放在授权动作旁，结果旁显示依据与缺项；不靠几屏说明让用户自行拼接心智模型。 |
| [IBM Carbon：AI label](https://www.carbondesignsystem.com/building-blocks/core/components/ai-label/guidelines) | 用稳定可辨认的入口通向解释；AI 标识不能只是装饰，也不应兼任“生成”等动作。 | 摘要里把“依据与范围”放在固定位置，清楚区分模型整理和原始来源；不新增一个无收益的 AI 图标/弹窗。 |
| [W3C WCAG 2.2：Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) | 成功、等待、进度和错误等状态应能被辅助技术感知，无须拿走输入焦点。 | 授权轮询更新 `role=status` / 适当 live region；不自动跳页、抢焦点或让按钮突然变成另一项不可逆动作。 |

这三套方法不能证明某个视觉风格“最好”，但能直接检验主动作、状态反馈与可核依据是否完整。

## 1. 把 Google 连接做成连续状态

现有 `src/client.js:354-468` 有状态轮询、来源按钮和问题草稿，不缺底层环节。缺口是各环节散在长页不同位置。已有连接截图首屏看不到授权按钮，顶部三个步骤无当前状态。

改为一个紧凑 Google 主卡，当前步骤与主动作同屏：

| 当前真实状态 | 用户看到 | 下一步 |
| --- | --- | --- |
| 尚未授权 | 这件事能得到什么；三项只读及模型/微信去向；未验证与可能限制 | 同意并连接 Google |
| 等本人处理 | 正在等待 Google 本人授权；倒计时；浏览器没打开的原链接 | 继续原授权；不重复提交 |
| 已保存，未启用 | 已保存在本机；列出实际授予的来源 | 选择并启用所需来源 |
| 已启用至少一源 | 已能使用哪些来源，尚未实际读取 | 紧邻可用来源展示一项具体问题；带入原生会话由用户发送 |
| 部分授权／取消／过期／错误 | 明确受影响来源、已有授权保留情况与安全恢复说明 | 继续已可用来源或重新连接，勿让用户找高级字段 |

必要披露仍可见；详细范围、管理与高级兼容折叠。账号授权、启用和实际读取仍是不同状态，视觉简化不等于合并权限。未来若承接用户原问题，应保留原范围并在授权完成后续办，不能由连接按钮新增扫描意图。

验收：常用 1452×702 首屏能看到收益、必要说明和当前主动作；授权成功返回后无需上下找下一步；普通账号路径不出现 Client ID/Token 输入；部分授权不展示虚假的全部成功。

## 2. 让“今天”只突出正在推进的事

现有今天页的输入框及项目选择已清楚；当前交办、异常和历史结果需要按任务关系排序。把“这次交代”维持为当前对象：本次草稿/执行状态靠前，需用户判断的阻塞相邻。旧回复放入有时间的历史折叠区；空状态给一项可做动作。

执行、通道排队、通道报告发送、用户验收分别呈现。来源或项目改变后，旧结果不得套上新标题。此处借鉴 OpenAI dot 的活动可追踪与 OpenClaw 的结果/通知分离，不复制它们的全部功能。

验收：已有一份旧回复时再开始任务 B，任务 B 始终可见；查看旧回复不触发重新派发；“完成”不暗示手机收到。

## 3. 结果旁给依据，状态在原位说清

项目、记忆页已经提供来源身份、时间和纠正入口，不应另造第二套来源详情。为 AI 摘要使用一致的“依据与范围”展开项，显示哪些来源、何时读取、哪些资料缺失/截断，并链接既有来源视图。让用户纠正时保留原来源身份和当前版本。

连接成功、保存成功和错误贴在对应卡片；用完整短句播报“Google 授权已保存，尚未启用来源”等状态。保留当前输入焦点；只有用户点击下一步才导航。不能把全页面堆满 live region，或每两秒重复播报不变状态。

验收：键盘走完授权/启用/首份问题；一次状态变化只读出一次；新结果的依据可从结果处打开；未知、裁剪和历史时间不可被漂亮摘要遮住。

## 评估边界

以上是基于一手资料与 0.15 代码/截图的设计判断，尚不是完成后的体验验收。落地后仍需隔离 Host 实走四页，覆盖成功、取消、超时、部分权限、凭据失效、已有草稿与第二项任务；手机实际到达和本人主观感受由相应层次单独验收。
