# 后续迭代

## 当前优先级（2026-10-21）

`0.11.0-preview.2` 是本地候选，原 App 仍运行 `0.10.0-preview.1`；源码回归、隔离宿主、真实模型、手机收件和公开发布分开核对，见[验证记录](verification.md)。本轮不迁移原计划、不扩大账号读取。

1. **Context 实际接通**：flomo/滴答已有官方账号授权入口，真实账号与有限读取待本人完成。Google Calendar 已有独立最小 OAuth/REST，但产品方 publisher 为空，普通登录仍准备中。先完成产品方应用身份和适用审核，再验明确时间窗；Gmail/Drive 逐源扩展，不把八个入口算作八个已接通账号。
2. **微信稳定好用**：先验准确原项目交办、单份结果、纯恢复不重派不复述，以及提醒到达时间；随后统一可理解的排队状态与低优先级通知预算。原 App 的另一项调试现场保留，本轮采用隔离官方宿主，不为升级中断现有任务。所有手机收件由用户本人确认，禁止微信客户端 UI 自动化。
3. **基于 context 的主动价值**：新增明确查询的项目变化卡，读取已关注项目三份固定文件与安全记忆，保留来源、角色、未知和截断。同可见资料静默，不代表全项目未变；独立水位按原会话/绑定/项目隔离。新卡未替换既有日报或主动跟进，先验内容质量，再由用户明确选择项目、频率和打扰条件后接入计划。
4. **资讯与日常汇报**：现有资讯支持本次明示主题预览，未保存兴趣或改变推送。下一步先预览确认少量兴趣，再考虑持久偏好、已读/无关反馈、跨推送去重与合并。92 个技术 RSS 不能宣传为已核实的 100 位 AI 作者；3＋7 是上限，不凑数。现有每日资讯任务保持原样。

Google 注册/真实授权、变化卡真实模型质量、新微信恢复、陌生用户开箱及休眠重连仍是验收缺口，不因自动测试通过而消失。Slack、Notion、云端 iCloud 与 iMessage 后置。

## 历史范围

`0.9.0-preview.2` 本机候选将确认的四点接入真实插件：首次微信收件确认、自然语言首页与执行详情、单次明确时间/周期跟进确认、记忆回执与纠正/遗忘。真实模块加载与页面操作需要宿主验收，手机送达另由用户确认。当前公开下载仍为0.6。

`0.8.0-preview.2` 源码候选新增已有目标、阻塞、下一步的只读工作台与可恢复的配对明暗外观。默认原生，可随时切回；其中记忆编辑已在0.9候选补入；确定性的微信恢复去重和长期主动质量仍待迭代。

`0.7.0-preview.1` 本机候选加入原生 Dot 侧栏入口及项目总览，已完成双 SDK 与原生界面验证，尚未公开发版。第一步让已有项目、来源、交办和提醒可见，后续再逐步增加会话内快捷入口、项目记忆纠错及更有用的变化摘要。

`0.5.0-preview.1` 已接入 AI 资讯日报，使用固定公开 RSS、用户现有 Harness 模型，以及最多 3 篇重点＋7 篇速览的独立发送流程；不复用私人配置或上游未授权的代码。使用与验证见[资讯日报](news.md)和[验证记录](verification.md)。

下一步优先积累真实阅读反馈：哪些摘要值得读、哪些来源经常失败、是否确实少花筛选时间；再验证连续多日、休眠和网络恢复。手机实际显示和送达由用户本人确认。

`0.6.0-preview.1` 加入 Google Workspace 六类来源、滴答、flomo 的原生配置、授权与按需只读连接。当前不自动订阅私人来源、不写回任务或文档。先完成用户本人的账号授权与有限范围验收，再考虑私人资料定时汇报。Slack、Notion、云端 iCloud、iMessage 后置。默认关闭的订阅和来源边界不因发布而放开。
